# Jarvis v6 需求文档

## 0. 服务架构分析

### 0.1 现有架构分析

当前贾维斯系统已经具备了多个独立服务，包括前端交互、大模型调用、用户处理、认知服务、边缘服务、数据服务、知识检索服务等。为了进一步提升系统的智能化水平，特别是在股票分析和决策方面，需要扩展现有finance服务的功能，使其具备大盘监控、股市新闻爬取、版块监控、个股盯盘等能力。

### 0.2 功能扩展方案

基于现有架构，我们将扩展jarvis-finance服务，增加股票相关功能，包括：

| 功能模块 | 功能描述 | 核心能力 | 优先级 |
|---------|---------|---------|--------|
| 大盘监控 | 监控指数变化 | 指数数据获取、趋势分析、阈值告警 | 高 |
| 股市新闻爬取 | 爬取财经新闻 | 多源新闻爬取、去重分类、情感分析 | 高 |
| 版块监控 | 监控版块指数变化 | 版块数据获取、热点识别、联动分析 | 高 |
| 个股盯盘 | 监控个股走势 | 价格监控、成交量分析、技术指标计算 | 高 |
| 股票买卖指标回测 | 回测买卖指标有效性 | 指标回测、成功率分析、历史数据管理 | 高 |
| AI决策分析 | 智能分析和决策 | 基于LLM的分析、投资建议生成、风险评估 | 高 |
| 通知系统 | 及时推送通知 | 前端通知、邮件通知、消息队列集成 | 高 |

### 0.3 扩展必要性

1. **功能完整性**：完善贾维斯系统的金融分析能力，提供全面的股票监控和分析功能
2. **性能优化**：将Finance服务迁移到Go语言，提升系统性能和并发处理能力
3. **技术栈优化**：合理使用不同技术栈，Go语言适合高并发的金融数据处理
4. **数据集成**：与现有数据服务无缝集成，实现数据共享和统一管理
5. **用户价值**：为用户提供智能化的股票分析和决策支持，帮助用户抓住投资机会

### 0.4 集成方案

1. **服务通信**：使用gRPC进行服务间高性能通信，REST API用于外部接口
2. **服务发现**：使用Nacos作为服务注册和发现中心
3. **配置管理**：使用Nacos进行统一配置管理
4. **消息队列**：使用RabbitMQ处理异步消息和事件
5. **缓存机制**：使用Redis缓存股票数据和计算结果
6. **数据存储**：使用MySQL存储结构化数据，如股票信息、新闻等

## 1. 需求背景

基于现有贾维斯系统的发展和用户需求的不断增长，需要增强系统的金融分析能力，特别是在股票监控和决策方面。现有系统已经具备了基础的股票价格获取和变动检测能力，但缺乏更全面的股票分析功能，如大盘监控、股市新闻爬取、版块监控、个股盯盘等。

通过扩展现有finance服务，整合股票相关功能，将使贾维斯系统具备更全面的金融分析能力，为用户提供智能化的股票监控和决策支持，帮助用户抓住投资机会，控制投资风险。

- **异常处理**：数据服务不可用时使用本地缓存数据

- **消息发送**：将监控和分析结果通过RabbitMQ发送到通知系统
- **频率控制**：控制通知频率，避免频繁通知
- **结果处理**：对通知结果进行处理，确保通知可靠送达
